# P1-scaleout Evidence

**Task ID:** P1-scaleout

**Goal:** Externalize Google Live `session_resumption` handles and Live-minute budget to Redis keyed by device id, front Python WS replicas with device-id affinity, and drain active sessions on SIGTERM.

## Scope

- `core/voice/live_admission.py` implements the Redis-backed live state store and async admission gate.
- `core/voice/session_provider/google_live.py` restores Redis resumption handles before opening Live, persists handle updates immediately, and records usage through the async budget interface.
- `core/connection.py` wires one live state store into both resumption and budget interfaces per connection.
- `core/websocket_server.py` rejects new device sockets during drain and waits for active connection tasks.
- `app.py` calls the drain path during shutdown.
- `deploy/docker-compose.prod.yml` runs Python WS replicas behind `tbot-wss-lb`, passes `REDIS_URL` into the Python service, and keeps Redis in the deploy stack.
- `deploy/haproxy.cfg` uses `balance hdr(device-id)` plus `hash-type consistent` for WSS affinity.

## Acceptance Evidence

- AC1: `RedisLiveStateStore` stores resumption handles under `tbot:live:{namespace}:session:{device_id}:resumption` and Live budgets under daily device/household keys. Covered by `test_live_budget_is_read_and_written_from_redis` and `test_budget_written_by_replica_a_is_enforced_by_replica_b`.
- AC2: `test_kill_replica_a_mid_session_then_reconnect_on_b_resumes` starts a real temporary Redis server, simulates replica A receiving a resumption update, drops replica A without a clean close, and verifies replica B restores the handle from Redis.
- AC3: `test_new_device_websocket_is_rejected_while_draining` and `test_drain_waits_for_active_connection_tasks_before_returning` cover SIGTERM drain semantics.
- Deploy: `test_prod_compose_fronts_ws_with_hash_affinity_lb_and_multiple_replicas` covers the WSS LB and replica topology; `docker compose -f deploy/docker-compose.prod.yml --env-file deploy/.env.example config` renders successfully.
