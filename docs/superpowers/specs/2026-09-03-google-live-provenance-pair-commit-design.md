# Google Live Provenance Pair Commit Design

## Status

Approved on 2026-09-03. This design closes the remaining Task 7 mixed-time
snapshot race without changing the public bytes or grammar of `commands.jsonl`
and `commands.txt`.

## Goal

Treat structured command provenance and its text projection as one committed
object. Readers must either observe one complete committed generation or fail
closed. A sequential read of the two public paths is never sufficient proof of
pair consistency.

## Storage Model

For a provenance path named `commands.jsonl`, the runner owns these hidden
control artifacts in the same bound parent directory:

- `.commands.jsonl.pair`: the atomic current-generation pointer;
- `.commands.jsonl.generations/`: a securely materialized private directory;
- `<generation>.jsonl` and `<generation>.txt`: immutable `O_EXCL` generation
  files containing the exact public JSONL and projection bytes.

Generation identifiers are random lowercase hexadecimal values generated by
the runner. The pointer is canonical JSON with a schema version, generation
identifier, fixed generation filenames, SHA-256 for both files, entry count,
and JSONL spec-digest summary. Pointer and generation contents are privacy
scanned and contain no command data beyond hashes and fixed safe names.

The public `commands.jsonl` and `commands.txt` remain exact compatibility
views. Their content and format do not change.

## Commit Protocol

The writer holds the pinned parent-directory flock and the validated provenance
lock for the whole protocol:

1. Bind and validate the current pointer and generation. For legacy evidence
   with no pointer, accept only a stable complete public pair (or both absent)
   and create an initial generation inside the transaction.
2. Create both new generation files with `O_EXCL|O_NOFOLLOW`, mode `0400`,
   bounded writes, file `fsync`, regular-file and single-link validation.
3. Atomically replace both public compatibility views with the new bytes and
   verify them against the new generation hashes.
4. Atomically replace and directory-`fsync` the pointer last. This is the pair
   commit point.
5. Rebind the pointer and generation and verify both public views. Only then may
   the transaction report success.

A failure before pointer publication leaves the old generation authoritative
and rolls public views back with the existing pair-wide CAS rules. A failure
after pointer publication treats the new generation as committed; rollback may
move the pointer backward only if its current inode/content still equals the
version published by this transaction. A newer pointer is never overwritten.

## Read Protocol

Readers use one helper shared by preflight, final verification, CAS, and
rollback verification:

1. Open and snapshot the pointer with `O_NOFOLLOW|O_NONBLOCK`.
2. Parse its exact canonical schema and safe generation names.
3. Open both generation files relative to the pinned generation-directory FD,
   validate mode/owner/link count, read with explicit size bounds, and verify
   both hashes and entry metadata from the pointer.
4. Re-open and re-read the pointer and require identical content plus identical
   inode, ctime, ownership, mode, and link count. This rejects pointer swaps and
   ABA restoration.
5. Verify both public views equal the pointer-bound generation bytes. A public
   mismatch fails closed; it is repaired only while holding both transaction
   locks.

The atomic pointer is the closing pair identity. Generation files are never
selected by scanning directory contents.

## Recovery And Cleanup

Under both locks, preflight may repair public compatibility views from the
current valid generation after an interrupted pre-pointer commit. It must not
repair an invalid pointer or unknown generation.

After a successful pointer commit and verification, the writer removes only
generation files that are proven unreachable from both the old and current
pointer and match the fixed generation filename grammar. Unknown files are
left untouched and cause cleanup to fail closed rather than broad deletion.
At most the current generation and one rollback generation are retained during
a transaction.

The pointer, generation directory, generation files, and lock are control-only
artifacts. They are excluded from command input/output provenance and must be
included in later Task 8 evidence-root policy explicitly.

## Tests

Tests are deterministic and hook driven:

- mutate JSONL after its final check and before projection validation;
- mutate projection in the inverse boundary;
- continuously alternate public views during bounded verification;
- replace, unlink, hardlink, and ABA-restore the pointer;
- inject failures after each generation write, each public-view replace, and
  before/after pointer publication;
- prove preflight never launches the child on an uncommitted or mismatched pair;
- prove final verification never publishes `PASS` for a mixed pair;
- prove rollback CAS preserves a newer generation and normal concurrent writers
  remain serialized;
- prove generation cleanup is bounded and never deletes current or unknown
  artifacts.

The existing command-runner, release-gate, reliability, compilation, lint, and
diff checks remain mandatory.
