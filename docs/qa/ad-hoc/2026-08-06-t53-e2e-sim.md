## Blocker

With everything above in place, the simulated device connects, sends `hello`, and the ESP server
**closes the socket with code 1000 (clean) without sending a single frame and without emitting
any server-side log line**:

```
[serial] websocket hello device_id=14:c1:9f:d1:a8:48 session=pending
FAIL: ConnectionClosedOK: received 1000 (OK); then sent 1000 (OK)
```

`docker logs tbot-ls-e2e-esp` shows nothing at all for the connection — not the auth-failure
path, not `Cannot get request path`, not `Error handling connection`. Close code 1000 means
`ConnectionHandler.handle_connection` **returned cleanly and immediately** rather than throwing
(an unhandled exception would surface as 1011).

Hypotheses tested and **refuted**:

| # | Hypothesis | Test | Result |
| --- | --- | --- | --- |
| 1 | Stale image (`local/tbot-server:latest` is from 2026-07-20, predating the August lesson work) | Re-ran on `local/tbot-server:main-dd48f39d-local-20260805` | Identical close |
| 2 | Client-side / port-mapping artifact | Connected from **inside** the container to `127.0.0.1:8000` | Identical close |
| 3 | `google_live` provider dials out at connection setup with no API key (why the in-process test stubs `_LiveClientStub`) | Switched sim config to `classic_pipeline`, restarted | Identical close — **not** the voice path |
| 4 | Device not claimed (`factory_test_claimed_all: false`) | Set `factory_test_claimed_all: true`, restarted | Identical close |

The sim config was reverted to `voice_mode: google_live` after hypothesis 3 — the
`classic_pipeline` switch was a one-shot diagnostic and is **not** carried in any committed file
(ground rule 1: the two voice paths stay separate).

**A silent clean close with zero logging on the device-connection path is itself a defect** —
it is a diagnostic black hole for anyone bringing up a robot, simulated or physical. It is
plausibly related to the live-capture stalls seen the same day
(`robot/evidence/lesson-e2e-2026080*` runs each fail 43/106 checks, all stalling right after
`lesson_start_requested`), though that link is **not** established.
